# Tarjeta de cambio — Incidencia de la hora 12 / CAC001

## Motivo

El reto anuncia una incidencia técnica durante la hora 12: el comprador
reporta un problema con `CAC001`. La aplicación debe bloquear el producto,
identificar origen y cantidades afectadas, conservar el historial y ejecutar
una prueba de regresión.

## Cambio implementado

- Se agregó el agregado de lotes con estados `PENDING`, `LIBERATED` y
  `BLOCKED`.
- `CAC001` inicia con 100 kg recibidos y 80 kg disponibles.
- Bloquear un lote conserva el evento anterior, agrega un evento hash-encadenado
  y una auditoría inmutable.
- La respuesta privada reporta origen, productor, cantidades afectadas y
  `history_verified`.
- La respuesta pública oculta razón y auditorías y marca el lote como no
  disponible para nuevos pedidos.

## Criterios de aceptación ajustados

1. `PATCH /api/v1/lots/CAC001/status` exige `status` y `reason`.
2. Una transición válida devuelve `BLOCKED`, `available_kg: 0` y
   `affected_kg: 80`.
3. La cadena de eventos permanece verificable.
4. No existe operación de borrado del historial.
5. Un usuario sin `lots:status` recibe `403`.

## Regresión ejecutada

```bash
python -m pytest tests/test_hour12_incident.py -q
```

La prueba cubre bloqueo, cantidades, auditoría, integridad, proyección pública,
permiso administrativo y detección de manipulación de payload.

## Alcance y reversión

El adaptador actual es en memoria para no tocar migraciones de Kevin. Para
revertir solo la funcionalidad de demostración se deshabilitan las rutas de
lotes; el contrato de pedidos, auditoría, blockchain e IA no depende de ellas.
